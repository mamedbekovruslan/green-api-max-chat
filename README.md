# MAX Chat · GREEN-API

Веб-интерфейс в стиле [web.max.ru](https://web.max.ru) для отправки и получения текстовых
сообщений MAX через [GREEN-API](https://green-api.com). Пользователь входит со своими
`idInstance` и `apiTokenInstance`, создаёт чат по номеру телефона и переписывается в реальном
времени.

## Возможности

- Вход по `idInstance` и `apiTokenInstance` с проверкой состояния и настроек инстанса.
- Новый чат по номеру телефона: номер проверяется в MAX, подтягиваются имя и аватар.
- История переписки из GREEN-API: при открытии чата загружаются последние 100 сообщений.
- Отправка сообщений: сразу видны в ленте, при ошибке — пометка и «Повторить».
- Получение сообщений и статусов в реальном времени: ✓ отправлено, ✓✓ доставлено, синие ✓✓
  прочитано.
- Непрочитанные: бейдж и превью в списке чатов, отметка прочитанным при открытии чата.
- Поиск по чатам, индикатор переподключения, работа с клавиатуры.
- Мобильная раскладка: на телефоне виден либо список чатов, либо чат со стрелкой «Назад».

## Быстрый старт

Нужен Node.js `^20.19.0` или `>=22.12.0` (требование Vite 8).

```sh
npm install
npm run dev
```

Откройте адрес из консоли (по умолчанию http://localhost:5173) и войдите с данными инстанса из
[личного кабинета GREEN-API](https://console.green-api.com). Поле «Адрес API» заполняется само
по первым четырём цифрам `idInstance`, но его можно изменить.

## Настройка инстанса GREEN-API

Инстанс должен быть авторизован (привязан к аккаунту MAX). В разделе «Уведомления» личного
кабинета:

| Настройка                                              | Значение | Зачем                                                    |
| ------------------------------------------------------ | -------- | -------------------------------------------------------- |
| Адрес отправки уведомлений (URL)                       | пустой   | иначе уведомления уходят на URL, а не в очередь HTTP API |
| Получать уведомления о входящих сообщениях и файлах    | включено | входящие сообщения                                       |
| Получать уведомления о статусах отправленных сообщений | включено | галочки доставки и прочтения                             |

Если что-то настроено не так, после входа приложение покажет предупреждение и предложит войти
всё равно.

**Бесплатный тариф Developer** позволяет переписываться только с тремя собеседниками в месяц.
При превышении GREEN-API отвечает ошибкой `466`, и приложение показывает «Превышен лимит тарифа».

## Стек

React 19, TypeScript (strict), Vite 8, TanStack Query, zustand, zod, CSS Modules. Тесты — Vitest,
Testing Library и MSW. Линтер — oxlint, форматирование — Prettier.

## Архитектура

Упрощённый [Feature-Sliced Design](https://feature-sliced.design): слои импортируют только слои
ниже, а слайсы — только через свой `index.ts`.

```
src/
  app/       — точка входа, провайдеры, запуск опроса уведомлений и подгрузки истории
  pages/     — экраны: login, chat
  widgets/   — sidebar (список чатов), chat-window (окно переписки)
  features/  — auth, create-chat, chat-history, send-message, receive-messages, mark-read
  entities/  — session, chat, message: типы, сторы, базовый UI
  shared/    — клиент GREEN-API, ui-кит, утилиты; ничего не знает о домене
  test/      — настройка тестов, MSW, фикстуры
```

- **Серверное состояние** (история, мутации) — TanStack Query. **Клиентское** (сессия, список
  чатов, непрочитанные) — zustand.
- **Все ответы API проверяются zod-схемами во время работы.** Типы TypeScript существуют только
  при компиляции и не гарантируют, что сервер прислал именно такие данные; zod проверяет
  реальный ответ, и неожиданный формат превращается в понятную ошибку, а не в падение
  интерфейса. Незнакомые уведомления и сообщения неподдерживаемых типов безопасно пропускаются.
- **Логика без React** — в чистых функциях (разбор уведомлений, нормализация номера, поллер),
  хуки только подключают их.
- **Получение сообщений** — функция `startNotificationPolling`, возвращает функцию остановки:
  - строго один запрос `receiveNotification` за раз: уведомление обрабатывается и удаляется
    через `deleteNotification`, и только потом запрашивается следующее — иначе одно уведомление
    можно получить дважды или не в том порядке («прочитано» раньше «доставлено»);
  - удаляются все уведомления, даже проигнорированные, иначе очередь встанет;
  - при ошибке связи — экспоненциальная пауза перед повтором (1, 2, 4… до 30 с), чтобы не
    засыпать запросами недоступный сервер;
  - остановка через `AbortController`, выход из аккаунта при `401`.

## Ключевые решения

- **`fetch`, а не axios.** Токен передаётся в пути URL, а `AxiosError` хранит `config.url` —
  токен легко утекает в логи и мониторинг. Наш `ApiError` содержит только тип ошибки и
  HTTP-статус; тела ошибочных ответов не читаются (в ответе `400` сервер возвращает путь запроса
  вместе с токеном).
- **Чат хранится по внутреннему `chatId` MAX.** Уведомления приходят с внутренним ID, а не с
  `номер@c.us`. Поэтому при создании чата номер резолвится через `checkAccount`, и отправка идёт
  на внутренний ID — это ещё и один слот квоты вместо двух.
- **Список чатов не загружается с сервера.** Сценарий задания — «ввести номер → создать чат»;
  массовое открытие чатов может исчерпать квоту бесплатного тарифа; проверяющий не видит сразу
  всю свою переписку. В списке — чаты, созданные в приложении, и чаты тех, кто написал.
- **История — с сервера, в браузере не хранится.** При входе история чатов подгружается по
  очереди, с паузой: у `getChatHistory` лимит — 1 запрос в секунду, при ответе `429` запрос
  повторяется до трёх раз. Из неё же восстанавливаются
  превью и непрочитанные (`isRead`) после перезагрузки.
- **Открытый чат с непрочитанными отмечается прочитанным** через `readChat` — как в web.max.
- **«Выйти» стирает из браузера всё**: сессию, список чатов и кэш. Чат легко создать заново,
  переписка подтянется с сервера.

## Безопасность

- Учётные данные хранятся в `sessionStorage` (до закрытия вкладки), с галочкой «Не выходить
  после закрытия вкладки» — в `localStorage`.
- Запросы уходят только на хосты `*.green-api.com` и `*.greenapi.com`: другой «Адрес API» форма
  входа не примет.
- В production-сборке действует Content Security Policy: скрипты и стили только свои, запросы —
  только к GREEN-API, картинки — свои и аватары MAX (`i.oneme.ru`).
- Текст сообщений выводится как текст, HTML не интерпретируется.
- В тексты ошибок не попадают ни URL запроса, ни тело ответа сервера.

## Ограничения

- **Токен виден в URL во вкладке Network DevTools** — так устроен API GREEN-API (токен в пути
  запроса), обойти это на клиенте нельзя.
- **История — в том объёме, в котором её хранит GREEN-API.** Сообщения, отправленные с других
  устройств (телефон, web.max) после подключения инстанса, и старые входящие до подключения
  сервер не отдаёт.
- Только текстовые сообщения и личные чаты: медиа, группы, редактирование и удаление — вне
  рамок задания.
- **Загружаются только последние 100 сообщений чата** — для тестового задания решено ограничиться
  этим числом. У `getChatHistory` нет постраничной загрузки (только общее количество `count`),
  поэтому подгрузка более старых сообщений не реализована.

## Тесты

```sh
npm run test
```

Около 290 тестов: клиент API и zod-схемы, поллер уведомлений, разбор уведомлений (определить
тип — сообщение, статус, превышение квоты — и достать текст, чат и время), сторы, компоненты и
сквозной сценарий «вход → новый чат → отправка → ответ → статусы». Сеть в тестах
подменяется через [MSW](https://mswjs.io), к GREEN-API тесты не обращаются.
